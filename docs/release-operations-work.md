A deletion request is hidden immediately in the database, then its worker publishes the independent journal before destructive completion. A crash between request and publication can leave an unjournaled in-flight request. Recovery therefore stays quarantined and requires live canonical eligibility; missing or unreachable source/journal evidence never authorizes automatic account reactivation. The journal contains account tombstones and the object paths observed by each deletion claim. Independent individual-file deletions are additionally checked against the current canonical inventory. Keep tombstones at least as long as every recoverable backup and review retention as part of the owner's policy. No tool claims the 8-hour RTO / 24-hour RPO targets have been achieved.

Historical evidence: the 2026-09-08 local logical restore and 67 HTTP check artifacts document that earlier source only. That logical restore excludes Storage object bytes and pg_cron. Use the current restore tools and new evidence for this release. Never put credentials, backups, tombstone identities, member/media paths or reviewer passwords into release evidence; retain aggregate results only.

## Current store requirements and submission work

These primary sources were checked on 2026-09-08. They are requirements to verify against the final binary and account, not evidence that Hittumst has met them.

- **Apple build/toolchain:** use Xcode 26 or later and the iOS/iPadOS 26 SDK or later for uploads; this requirement has applied since 2026-04-28. Retain the EAS build image/toolchain and archive evidence. [Apple submission requirements](https://developer.apple.com/app-store/submitting/).
- **Android target/build:** new apps and updates must target Android 16 / API 36 starting 2026-08-31. Verify the generated release manifest, native dependencies and 16 KB page-size behavior, not just an Expo setting. [Google target API requirements](https://developer.android.com/google/play/requirements/target-sdk), [Android page-size compatibility](https://developer.android.com/guide/practices/page-sizes).
- **Billing:** Google Play Billing Library 7's submission deadline was 2026-08-31; validate that the actual subscription SDK resolves to a currently supported Billing Library, ordinarily 8 or later. Provider configuration and renewal/refund/restore tests remain required. [Google billing support timeline](https://developer.android.com/google/play/billing/deprecation-faq).
- **Accounts and deletion:** Apple requires initiating account deletion in-app and directs Sign in with Apple integrations to revoke Apple tokens. Google requires an in-app deletion path plus a web resource for requesting account/data deletion. Verify full user-content cleanup, ownership checks, explicit retained-data explanations and subscription cancellation guidance. [Apple deletion guidance](https://developer.apple.com/support/offering-account-deletion-in-your-app/), [Google account deletion requirements](https://support.google.com/googleplay/android-developer/answer/13327111).
- **Privacy and native SDKs:** complete Apple privacy details, Google Data Safety, permission disclosures, vendor data-flow review, required-reason API declarations and applicable third-party SDK privacy manifests/signatures from the final binary. All owner/legal/processor statements remain unapproved. [Apple privacy details](https://developer.apple.com/app-store/app-privacy-details/), [Apple SDK requirements](https://developer.apple.com/support/third-party-SDK-requirements/), [Google user-data policy](https://support.google.com/googleplay/android-developer/answer/10144311).
- **User-generated content and safety:** provide working reporting, blocking, content filtering and reachable support; verify active moderation/escalation and child-safety obligations for the selected dating/social categories. Because dating is core functionality, configure Play Console Restrict Minor Access and complete the actual age/content questionnaires. Adult-only status does not remove the child-safety obligations. Product differentiation and review notes also need owner review. [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/), [Google child-safety standards](https://support.google.com/googleplay/android-developer/answer/14747720?hl=en-419), [Google age-restricted functionality](https://support.google.com/googleplay/android-developer/answer/16302250?hl=en).
- **Publisher/test eligibility:** confirm developer identity, agreements, tax/banking where relevant, bundle/package ownership, App Store Connect/Play Console access, App Signing and upload-key recovery. If the Play account is a personal account created after 2023-11-13, Google requires at least 12 continuously opted-in closed testers for 14 days before applying for production access. The account type has not been verified. Confirm the app is registered to the verified developer in Play Console under the current developer-verification requirements. [Google personal-account testing requirements](https://support.google.com/googleplay/android-developer/answer/14151465), [Google July 2026 policy announcement](https://support.google.com/googleplay/android-developer/answer/17134731?hl=en).
- **Store material:** review docs/store-submission.json, select supported locales/territories and the real public URLs, produce screenshots from the final signed iPhone/iPad/Android builds, verify asset rights, prepare accurate screenshots/descriptions and supply restricted reviewer access without putting credentials in source control.

No signed EAS build history was found in the root agent's check, and no connected Android physical device was available.
