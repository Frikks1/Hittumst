# Admin, public web and operations feature verification

Updated 21 September 2026. This is the authoritative companion to [the mobile inventory](feature-verification.md) for the source under `apps/admin/src`. Together they cover the app's screens and supporting workflows. Source and test references establish what is implemented and what the tests exercise; they do not establish deployed, browser, device or provider acceptance. Record those results in the [release checklist](release-checklist.md).

The staff browser navigation contains Overview, Reports, Photo review, Media appeals, Finance review and Audit log. Finance review is explicitly sandbox-only. A support inbox, alert dashboard or external provider account is not implied by an API.

## Evidence and gaps

Current aggregate evidence belongs under `artifacts/operations/`: `admin-production-http.json`, `docker-runtime.json`, `database-release-rehearsal.json` and `local-restore.json`. The real-service detail is `tmp/service-workflows-result.json`. Failed/running reruns must not be presented as prior success; use completion times, source/migration fingerprints and the release evidence gate. No route table substitutes for actual interactive UI acceptance.

The principal unresolved operator capabilities are verified external support/alert coverage, approved and integrated real financial rails/rules, and deployed recovery/capacity drills. The prepared financial console supports rehearsal against sandbox contracts; production operator acceptance depends on those real adapters. Browser accessibility and real staff decision flows also remain acceptance work. Do not mark every feature verified until these and the mobile/provider/device requirements have evidence.
