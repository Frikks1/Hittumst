## Remaining engineering and acceptance boundaries

Production finance is the known unfinished implementation. The current commerce APIs, worker and finance console require the isolated sandbox, and the worker instantiates a sandbox provider. Production subscription readiness is hard-coded closed. Approved provider contracts must define the actual currencies/units, identity checks, custody, fees, limits, settlement, refunds/disputes and voucher catalogue before the corresponding production adapters and funded grant/reserve controls can be completed. No environment switch substitutes for that work. RevenueCat's latest-period snapshots also need a provider-supported history/reconciliation procedure for any paid periods missed before integration; pending cash liabilities cannot be treated as spendable funds.

Account deletion is implemented with durable retry, not guaranteed instant external completion. Missing Apple credentials allow deletion with official manual revocation instructions; any stored token is revoked and provider errors remain pending. A RevenueCat customer merged with another live account requires safe provider/operator resolution. Account deletion does not cancel store subscription billing. Actual retention, support handling and provider-erasure confirmation still require acceptance.

Fresh admin HTTP/container checks, hosted deployment, full recovery/capacity drills, interactive staff UI checks and physical-device/provider tests remain verification work; any failures require fixes before launch. See [external launch blockers](external-launch-blockers.md) and all 14 closed [readiness gates](launch-readiness.json).
