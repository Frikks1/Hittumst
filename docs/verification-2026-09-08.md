## Failures found and corrected

- Historical expansion migration referred to a nonexistent profile avatar column and a deletion helper that existed only inside a commented appendix.
- Conversation creation and occurrence room creation/membership had ambiguous SQL variables that broke real operations.
- An album policy compared a share's ID to itself instead of the outer album ID. Accepted recipients can now retrieve authorized metadata.
- The peer-block expansion had overwritten host-block revocation. Host blocking now removes participation, while peer conflicts pause room access and preserve RSVPs. Unblocking does not restore either automatically.
- Locked event rooms incorrectly lost reading access at the posting deadline. Authorized reading now continues to the separate reading deadline.
- Message history uses timestamp/ID seek cursors, caps results at 50 and preserves IDs on retry. Occurrence room sends return their own acknowledged message instead of guessing the last history item.
- Moderator access now requires MFA and current protected roles, including when an old token still claims an admin role.
- Shared date validators now accept PostgreSQL's explicit UTC-offset wire format without discarding sub-millisecond precision.
- Late admissions have a real fifteen-minute confirmation window capped by the effective event end. Expired pending participants lose protected details and room access without waiting for a background job. Explicit rejoining starts a new confirmation window; removal is never undone implicitly. The mobile detail screen refreshes authorization on foreground and clears private details on background.
- The push worker no longer drops numeric PostgreSQL outbox IDs. Its payload tests verify generic Icelandic/English previews with only a notification ID, excluding message bodies and addresses.

The old pgTAP fixtures also used incorrect overloads and attempted direct reads of private staff/viewer tables. They now test supported RPC access and inspect privileged fixture state only as the test operator. Synthetic location freshness is refreshed inside test transactions.

## Reproduce

On Linux with Docker: `supabase start`, `supabase db reset`, `supabase test db`, then `supabase db lint --local --schema public,private --level error --fail-on error`.

On this Windows workspace, while the synthetic local database is running: `npm run db:test:local`. Application checks: `npm run check`. Production publication additionally requires the operational evidence in `launch-readiness.json` and a passing `release:preflight`.
